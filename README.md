# OCR text recognition (ocr)

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This repository is an extension package for Miyu that extracts the Chinese and English text in images on your own computer. It works as soon as it is installed, and you do not need to install Tesseract, Python or similar software separately.

The commands to install and use it are:

```sh
miyu pkg install ocr
miyu ocr 截图.png        # Recognize one image on the command line
miyu ocr                 # Check whether the models have finished downloading
```

The AI uses the tool `ocr`: you pass the path of an image (relative to the workspace, or absolute), and the tool returns the text line by line, from top to bottom. It reads PNG, JPEG, WebP, GIF, BMP and TIFF, and photos taken with a phone are turned upright according to their EXIF data. `clicall`: the AI can use `miyu call ocr` in a command to recognize images in bulk, and the script gets `{"lines": [{"text", "box", "score"}]}`.

## How recognition works

This section describes the models the package uses, how it downloads them, and the resources it takes.

- It uses the mobile models of [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR): PP-OCRv5 to detect where the text is, and PP-OCRv4 to recognize the text. The models run on [RTen](https://github.com/robertknight/rten), written in pure Rust, so the program carries no C libraries, builds the same way on all three systems, and is about 8 MB each.
- The models are not shipped with the package: on first use they are downloaded from the [oar-ocr release](https://github.com/GreatV/oar-ocr/releases/tag/v0.3.0) (about 16 MB), used only after passing a check against a pinned SHA-256, and stored in this package's cache folder. The program starts downloading in the background as soon as it starts, so the first call does not have to wait. The download uses the system's proxy settings. If it cannot connect, gets no response, or receives no new data for 30 seconds during the download, it reports an error and downloads again on the next call; a slow connection that keeps downloading has no time limit.
- When there is nothing to recognize, it takes only about 8 MB of memory: each recognition starts a separate child process that reads the models on the spot (a few tens of milliseconds), and the child process exits when recognition is done, returning all the memory it used to the system.
- Large images are cut into horizontal strips for text detection, so even the longest screenshot only takes the memory of one strip.

These figures were measured on a 12-core Linux computer:

| Image | Time | Peak memory |
|---|---|---|
| A short screenshot (900×260, 4 lines) | 0.1 s | about 70 MB |
| A full-screen screenshot (1920×1080, 20 lines of mixed Chinese and English) | 1.1 s | about 180 MB |
| A very long phone screenshot (1080×6000, 60 messages) | 2.5 s | about 195 MB |

## Accuracy

The screenshots, documents, web pages, dark mode, serif fonts and 12-pixel small text that were tested, saved as either PNG or JPEG (quality 50 to 85), were recognized completely or missed only the odd punctuation mark or space. Recognition does not work well on:

- Text photographed at an angle, and vertical text: the boxes used to detect text are axis-aligned;
- Handwriting;
- Japanese kana and Korean: the recognition model only covers Chinese, English, digits and common symbols.

### Why recognition uses v4

The mobile recognition model of PP-OCRv5 drops whole characters on JPEG-compressed images: after a full-screen screenshot is saved as JPEG (quality 80), common characters such as `一`, `行`, `用` and `文` go missing in large numbers, and only 18% is recognized correctly; the same image saved as PNG is recognized entirely correctly. Switching to another conversion (the one from RapidOCR) or running it with ONNX Runtime gives the same result, which shows the problem is in the model itself. The mobile model of PP-OCRv4 recognizes the same set of images completely in both PNG and JPEG, and is 6 MB smaller. Because most images sent in chats are JPEG, the package uses v4.

## Development

During development, you can use these commands:

```sh
cargo test --workspace
cargo xtask licenses     # Check that the third-party licenses are compatible and that THIRD-PARTY-LICENSES.txt is up to date
cargo xtask notices      # Regenerate the list after upgrading dependencies
```

To publish a new version, push the tag `v<version>`; `.github/workflows/release.yml` builds one `.miyu` file for each of the three systems.
